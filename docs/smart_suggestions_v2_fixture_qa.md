# Smart Suggestions v2 - Fixture QA

## 1. Scope

This QA note reviews the deterministic Smart Suggestions v2 fixture and the demo loader that supports local approval UI testing without an API key.

No runtime behavior changes are part of this QA block.

## 2. Fixture Purpose

The fixture exists to make Smart Suggestions v2 testable without `OPENAI_API_KEY`.

It supports two needs:

- parser safety coverage in pytest
- manual approval UI testing in Streamlit with deterministic demo records

The fixture is not product data and is not real AI output.

## 3. Fixture Coverage

Fixture file:

`tests/fixtures/smart_suggestions_v2_demo_response.json`

The fixture covers:

- a normal pending/review-required description suggestion
- a high-risk warning note suggestion that remains review-required
- an unsupported factual EAN suggestion that becomes blocked
- a missing source/reason attributes suggestion that becomes blocked
- an AI-supplied approved product title suggestion that is downgraded to needs review

This gives the approval UI enough states to test visible pending, review-required, high-risk, blocked, and approval-downgrade behavior.

## 4. Parser Test Coverage

Parser fixture tests are in:

`tests/test_suggestion_parser.py`

The tests verify:

- the fixture parses as valid JSON
- all fixture records normalize safely
- AI-supplied approved status does not remain approved
- blocked records remain blocked
- unsupported factual fields are blocked
- missing source/reason cases are blocked
- high-risk records remain visible but review-required

This confirms that the fixture uses the same parser safety path as real V2 responses.

## 5. Demo Loader Behavior

The Streamlit loader appears inside the existing Smart Suggestions v2 experimental section:

`Demo fixture for Smart Suggestions v2`

Button:

`Load demo Smart Suggestions v2 records`

Observed from code inspection:

- the loader reads the deterministic fixture file
- it parses fixture data through `parse_and_normalize_suggestions(...)`
- it stores records only in Smart Suggestions v2 session-state keys
- it resets V2 review decisions when demo rows are loaded
- it labels the source as `demo_fixture`
- it shows wording that the records are deterministic test data and not generated by OpenAI

## 6. Approval UI Testability Without API Key

The fixture loader makes the approval UI testable without an API key.

Expected manual flow:

1. Start the app.
2. Open the AI Suggestions tab.
3. Open Smart Suggestions v2 experimental section.
4. Expand `Demo fixture for Smart Suggestions v2`.
5. Click `Load demo Smart Suggestions v2 records`.
6. Confirm rows appear in the structured V2 table.
7. Confirm the human review section appears.
8. Approve a non-blocked row.
9. Reject a non-blocked row.
10. Confirm a blocked row cannot be approved.
11. Confirm decisions are session-only.

## 7. Safety Checks

The current fixture/demo path preserves the safety boundaries:

- demo records are clearly labeled as deterministic fixture data
- fixture loading requires no API key
- V1 AI Suggestions remain separate
- V2 real generation remains separate
- fixture rows are not exported
- fixture rows do not write back to product data
- blocked rows remain non-approvable
- AI-supplied approval is downgraded by parser behavior
- review decisions are stored only in Streamlit session state
